The Situation

Two Tools, Neither Fully Functional

What I Inherited

Salesforce had two import tools of its own, built at different times by separate product teams with completely inconsistent style guides and locations, and customers had filled the gap with three more import apps on the AppExchange, the Salesforce marketplace. Neither of Salesforce's own tools was fully functional. Admins had no idea where to go, what files to prep, or why bad data kept breaking production schemas. Years of bad imports had compounded into a systemic platform trust problem.

How I Found the Problem

I benchmarked 15+ competing import tools, including Oracle, Microsoft Dynamics CRM, Podio, SugarCRM and Informatica. I mined Salesforce's public Idea Exchange for the fixes people wanted most, with requests drawing up to 540 community points: saved field maps, multi-line street address mapping and default values. And I mapped the existing flow: eight steps scattered across the Setup tree.

The Opportunity

These were not two small problems. They were one trust problem. The instructions were inconsistent, the mapping fields were unknown, and nothing validated the data before it was committed to the CRM. One trusted flow could fix all of it at once.

The Bet

One Location. One Name. One Entry Point.

The first decision was the simplest and the hardest: one location, one name and one entry point, so the import was finally discoverable. Everything after that served one idea: guide the admin down a single clear path, and never let dirty data reach production.

The Path I Designed

Six Phases, One Clear Path

Overview
Orient the user, set expectations and explain what they need before they start.
Phase 2
File prep
Guide them through getting their CSV ready before upload.
Phase 3

Drag and drop, with clear file type guidance.

Data display

Phase 5
Clean

Phase 6
Confirm
The data is in Salesforce, ready to use.
Craft Decisions

Six Moves That Mattered

1. One Product, Not Two

The batch size was set to handle 80% of users in the standard flow, with bulk available for the rest. That served both audiences without splitting into two products.

2. Preview and Clean Before Commit

A preview and cleaning step before the commit eliminated years of dirty data entering production systems.

3. One Place to Start

One location, one name, one entry point. The thing admins could never find became the thing they could not miss.

4. Plain Language, Written With a Copywriter

Every step had to be understood, not just seen, so the copy was written with a copywriter instead of left to the interface.

5. I Coded Part of the Prototype Myself

I built part of the prototype in code to validate the interaction model before engineering built it. It is the same reason this page has a working demo.

6. Progress That Talks Back

The progress bar did more than count. Choose data, edit mapping, start import, with small encouragements along the way: Let's do this, Good job, Getting closer, Almost done, Great job. Import is a task people dread, so the interface cheers them on.

Impact & Outcome

What It Added Up To

The prototype passed usability testing with seven representative user roles, and Salesforce piloted the wizard in 2013. Five tools became one trusted, elegant wizard, released to every Salesforce customer in 2014, and dirty data imports dropped dramatically across the platform. Then it spread: competitors copied the exact flow, a category of venture-funded CSV-import startups now sells this interaction to other software companies (OneSchema raised a $6.3M seed in 2022, Flatfile a $7.6M seed in 2020), and it is still regarded as the standard for CRM data import UX.

Design systems so elegant that users forget they are systems.
